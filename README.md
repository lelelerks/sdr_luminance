# SDR Luminance

Windows 11 HDR 模式下的 **SDR 内容亮度**快捷调节工具。

开启 HDR 后，桌面、网页、聊天软件等 SDR 内容的显示亮度由系统的「SDR 内容亮度」参数控制。
该参数藏在「设置 → 系统 → 屏幕 → HDR」四层菜单之下，且没有任何快捷键——偏偏最需要调它的时刻，
是全屏游戏或全屏观影当中。

本工具把这个参数拎出来：一个常驻托盘的小窗口，拖滑杆即时生效；最小化后用全局快捷键调节；
窗口浮在全屏程序之上，可以一边看游戏画面一边调。

## 特性

- **实时调节**：拖动滑杆亮度即时变化，与系统设置页的 0–100 刻度一一对应
- **全局快捷键**：程序隐藏在托盘时也能调亮度、唤起窗口；长按连发
- **调节时自动显示数值**：窗口收在托盘时按快捷键，窗口会自动弹出让你看清当前值，停手后自动收回
- **完全可自定义**：三个快捷键、调节步进值与弹窗停留时长均可在设置页修改
- **不抢焦点**：点击窗口、拖动滑杆都不会让前台的全屏游戏失焦或掉出全屏
- **非 HDR 时明确提示**：未开启 HDR 时界面置灰并说明原因，不静默失效
- **开销极小**：单文件 exe 约 180 KB，常驻内存约 2 MB，空闲 CPU 占用 0%，无任何外部依赖

## 使用

直接运行 `SdrLuminance.exe`，无需安装。

| 操作 | 方式 |
|---|---|
| 调整亮度 | 拖动窗口中的滑杆 |
| 隐藏窗口 | 点右上角关闭按钮（程序继续在托盘运行） |
| 唤起／收起窗口 | 快捷键，或单击托盘图标（均为开关，再按一次即收起） |
| 打开设置 | 窗口右下角「设置…」按钮，或托盘图标右键菜单 |
| 退出程序 | 托盘图标右键 → 退出 |

### 默认快捷键

| 功能 | 组合键 |
|---|---|
| 调亮一档 | `Ctrl + Alt + PageUp` |
| 调暗一档 | `Ctrl + Alt + PageDown` |
| 唤起窗口 | `Ctrl + Alt + B` |

默认步进为 5（对应 20 nits）。三个快捷键与步进值都可以在设置页改。

在设置页的输入框中**直接按下组合键即可录制**；按 `Backspace` 或 `Delete` 清除该项绑定。

### 调节时自动显示数值

窗口收在托盘时按调亮/调暗快捷键，窗口会**自动弹出**显示当前数值，停手约 1.5 秒后自动收回托盘。
弹出过程同样不抢焦点，全屏游戏不会失焦或掉出全屏。

停留时长可在设置页修改（500–10000 毫秒）。计时从**最后一次**按键起算，所以长按连发期间窗口会一直留着。

窗口本来就开着时，快捷键行为完全不变——不会自动消失。

自动弹出后若你主动操作了，窗口即转为常驻不再自动消失。**点窗口任意位置**（空白处、标题栏、滑杆、按钮）
是最直接的方式，点托盘图标或打开设置页同样有效。

注意「唤起窗口」键是**开关**，不算主动操作：自动弹出后按它会直接把窗口收起来。想留住窗口请点它一下。

### 快捷键被占用怎么办

全局快捷键是先到先得的系统资源。若某个组合已被其他常驻程序注册，本程序会明确提示是哪一项、
错误码是多少，**其余快捷键不受影响仍可使用**，在设置页改绑即可。

一个附带现象：已被其他程序占用的组合，在录制框里根本按不进去——按键会被占用方先行截获。
所以你在 UI 上通常不会设出一个必然失败的组合。

### 开机自启动

设置页与托盘右键菜单都有「开机时自动启动」开关，两处共享同一状态（以注册表为准）。
启用后写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，**不需要管理员权限**。
自启动时程序直接收进托盘，不弹窗口。

程序文件被移动后，下次启动会自动修正注册表中记录的路径，无需手动重新开关。

## 已知限制

### 独占全屏模式下窗口不可见

当前台程序运行于**独占全屏（Exclusive Fullscreen）**模式时，本工具的窗口不会显示在其上方。

这是 Windows 桌面窗口管理器（DWM）的硬性行为——独占全屏下应用直接接管显示输出、绕过桌面合成，
**任何常规窗口都无法覆盖其上**，与本程序的实现方式无关。

**全局快捷键在独占全屏下仍然完全有效**，只是看不到窗口界面。

解决办法是把游戏切换为「无边框窗口化」（Borderless Windowed）模式——这也是当今绝大多数游戏的
默认设置，在现代 Windows 上与独占全屏已无实质画质与性能差异。

> 唯一的技术规避方式是向游戏进程注入 DLL 并 Hook 其 D3D 交换链绘制 overlay。该做法极易被反作弊
> 系统判定为外挂导致封号，且开销与复杂度剧增，本项目明确不采用。

### 仅作用于主显示器

多显示器环境下只调节系统主显示器。副屏请用系统设置页调整。

### 依赖非公开 API

写入 SDR 白电平所用的接口 Microsoft 未公开文档化。该接口自 Windows 10 1709 起持续可用，
但未来的系统更新存在改变或移除的可能。若失效，程序会在状态栏给出明确错误提示而非静默失败。

排查时可用 `probe.exe` 快速定位是系统接口变更还是程序自身问题：

```
probe.exe            仅查询，只读不修改
probe.exe set 50     设置滑杆值并回读校验
probe.exe demo       30 → 70 → 恢复原值
```

## 构建

需要 MSVC 工具链与 Windows SDK 10.0.22621 以上（`DISPLAYCONFIG_GET_ADVANCED_COLOR_INFO_2` 需要）。

```
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

产物位于 `build\Release\`：`SdrLuminance.exe`（主程序）与 `probe.exe`（诊断工具）。

Release 配置启用了静态 CRT 与 LTCG，产出的 exe 不依赖任何运行时库。

### 修改代码后重新编译

改完代码**不需要重新执行 `cmake -S . -B build`**，直接构建即可，CMake 只重编受影响的文件：

```
cmake --build build --config Release
```

分情况：

| 改动内容 | 需要做的事 |
|---|---|
| 只改了 `src/*.cpp` / `*.h` 的内容 | 直接构建，增量编译 |
| 新增或删除了源文件 | 先在 `CMakeLists.txt` 的 `add_executable` 中增删对应行，再构建 |
| 改了 `CMakeLists.txt` | 直接构建即可，`ZERO_CHECK` 目标会检测到变更并自动重新生成工程 |
| 构建结果异常、怀疑缓存脏了 | 删掉整个 `build\` 目录，重新执行上面「构建」一节的两条命令 |

**构建前务必先退出正在运行的 `SdrLuminance.exe`**（托盘图标右键 → 退出）。程序运行时 exe 文件被占用，
链接器会失败并报 `LNK1168: 无法打开 ... 进行写入`。

调试时用 Debug 配置，产物在 `build\Debug\`：

```
cmake --build build --config Debug
```

在 VS Code 中（CMake Tools 扩展）按 `F7` 构建。注意实际生效的构建类型由**状态栏的变体选择器**决定：
Visual Studio 是多配置生成器，`CMAKE_BUILD_TYPE` 会被忽略，起作用的是构建时传入的 `--config`。
若想验证 Release 的 `/O2 /GL /LTCG` 是否生效，必须把变体切到 Release，光看配置日志里的 Debug 字样说明不了问题。

## 技术说明

系统「SDR 内容亮度」滑杆对应显示器的 **SDR 白电平**参数：

```
nits          = 80 + slider * 4          // slider 0..100 → 80..480 nits
SDRWhiteLevel = 1000 + slider * 50       // → 1000..6000
```

读取走公开 API `DISPLAYCONFIG_DEVICE_INFO_GET_SDR_WHITE_LEVEL`，写入走 `DisplayConfigSetDeviceInfo`
的一个非公开 info type。写入结构体带一个 `finalValue` 标志：置 0 时亮度立即生效但不写入系统持久化
配置，置 1 才落盘。本程序在拖动滑杆与快捷键连发期间传 0，停手后才传 1——这消除了连续调节过程中
每秒几十次的系统配置写入。

HDR 状态检测优先用 `DISPLAYCONFIG_DEVICE_INFO_GET_ADVANCED_COLOR_INFO_2`（枚举值 **15**，注意不是 14），
失败时回退到 `GET_ADVANCED_COLOR_INFO`。状态变化完全由 `WM_DISPLAYCHANGE` 消息驱动，全程无轮询——
这是空闲 CPU 能保持 0% 的前提。
